# 引擎按月计算：计划

## 目标

界面和节奏**不变**：屏幕上仍然一年一年地走（1× 时一年约 46 秒），进度条仍然代表一年。
变的是引擎内部：每一年切成 12 个月，**以月为基本单位**结算钱、判定风险、安排事件和抉择。
一年之内的先后和时长因此变准：几月失业就从几月起没有工资、几月确诊、治疗几个月、怀孕十个月、中考高考在 6 月、开学在 9 月。

## 已经做好的（核心骨架，提交在 `main`）

- `src/engine/monthly.ts`：时间模型和换算工具（见下）。
- `src/engine/lifecycle.ts`：推进循环已经按月走。每跨过一个月的边界：先触发这个月里排到的事，再调用 `endMonth(m)`；第 12 个月结算完调用 `endYear()`（长一岁、排下一年）。无界面的人生（同伴、校准）用同一个循环（`runHeadlessYear()` = `tickTo(1)`）。
- 原来「年初」「年末」的每一步都拆成了钩子，放在各领域自己的文件里。**现在是兼容模式**：每个月末的钩子只在第 12 个月（`m === 11`）做原来年末的那一步，其他月份什么都不做。所以模拟结果和改造前完全一样（70 个人生的完整状态逐字段相同，只多了 `S.month`）。
- 校准基准：`docs/monthly/baseline/*.txt`，是改造前（也就是兼容模式）所有校准脚本的输出，用来对照。

**你的任务：把你负责的钩子从「第 12 个月做一次一年的量」改成「每个月做一个月的量」。**

## 时间模型

- `S.month`：这一年的第几个月，0 = 生日那个月，11 = 下一个生日前的那个月。
- `S.t`：这一年过了多少（0–1）。第 m 个月从 `monthStart(m) = m/12` 开始。
- `posIn(m, frac)`：第 m 个月里的一个位置（排事件用）。
- `calMonth(m)`、`calYear(m)`：第 m 个月是公历几月、哪一年；`monthOfCal(cm)`：公历 cm 月是这一年的第几个月。
- `S.age` 仍然在生日那个月加一（`endYear`）。

## 换算规则（`monthly.ts`）

| 原来按年的东西 | 按月的写法 |
|---|---|
| 一年内发生的概率 p | 每月 `chance(perMonth(p))`：状态不变时 12 个月累计正好是 p |
| 每年向目标值靠拢 `x += (T − x) × k` | 每月 `x += (T − x) × approachPerMonth(k)` |
| 每年一次的正态波动 `gauss(0, sd)` | 每月 `gauss(0, sdPerMonth(sd))`，一年的方差不变 |
| 一年的金额（工资、开销、房租…） | 每月 1/12，按**当月的实际状态**记 |
| 每年抽一次的随机量（个体户收入波动、房价涨跌） | 仍然每年抽一次（在第 0 个月），再摊到 12 个月 |
| 年度利率 r | 每月 `(1 + r)^(1/12) − 1`（用 `fpow`） |

状态不变的一年，换算后的年度统计应该和原来一样；差异只应来自「一年之内状态变了」，这正是想要的。

## 必须遵守

1. **确定性**：同一个种子 + 同样的输入 = 同样的人生。只用 `rng.ts` 的 `rnd/chance/gauss/pick/wpick`，数学函数只用 `fmath.ts` 的 `fexp/flog/fcos/fpow`（有测试检查 `src/engine` 里不能出现 `Math.exp` 等）。日常（`content/daily.ts`）只用 `rnd2`。
2. **只改自己负责的文件**（见分工表）。别人的文件、`lifecycle.ts`、`monthly.ts`、`types.ts`、界面（`src/ui`、`src/game`）都不要改。需要别人那边配合的，写进最后的报告，由合并的人处理。
3. **需要给 `Life` / `Flags` 加字段**：不要改 `types.ts`，在你自己的文件里用模块扩充：
   ```ts
   declare module './types' { interface Flags { preg?: { due: number } } }
   ```
4. **不要提交 `tests/golden.json`**（会和别人冲突）。快照测试失败是预期的，合并以后统一重建。其余测试（`replay`、`daily`、`fmath`）必须通过。
5. 每个月都要跑的代码要轻：一个月几微秒的量级。改完量一下 `npm run calib -- sim 3000` 的耗时，和改之前比。
6. 注释、提交说明用中文，风格和现有代码一致。

## 分工

### A：钱（`finance.ts`、`household.ts`、`housing.ts`、`turns.ts`）
钩子：`moneyMonth(m)`（以及 `turns.ts` 的 `turnsYear` 里和钱有关的部分）。
- 你自己的账每月结算：在职的月份才有工资（年中换工作、裁员、退休、找到工作都按月）；生活开销、养孩子、房租每月记；房贷每月扣（等额本息本来就是按月算的）；公积金每月缴、每月提取；存款和欠款利息按月复利。注意 `finance.ts` 里已有按 `S.t` 折算工资的 `accrueWage`，统一成按月以后可以简化。
- 储蓄率模型用「年化」的收入算（当月收入 × 12），保持原来的含义。
- 父母家的账（`household.ts`）同样按月：收入、结余、还欠款、子女补贴；学费在开学时（公历 9 月）一次交或按月摊，自己选，写清楚。
- 个体户、小老板的收入波动、房价涨跌：每年在第 0 个月抽一次。
- `S.income` 继续表示「现在的年收入」（界面显示用）；一生曲线里的存款由核心在第 12 个月记。
- 返聘收入、候鸟的开销按月。
- 对照：`wealth`、`debt`、`loan`、`sim`（买房比例、职业）、`crisis`、`edge`。可以微调 `SAVE_BASE` 等系数，写明理由。

### B：生死与家人（`mortality.ts`、`health.ts`、`family.ts`、`kin.ts`、`parents.ts`）
钩子：`healthMonth(m)`、`familyMonth(m)`、`sibYearStart()`、`kidsYearStart()`、`conceive()`。
- 你自己的死亡：每月 `perMonth(deathProb())`；确诊大病也按月。治疗中的大病按月判定（原来的年死亡率换算成月），复查、吃药的开销按月；确诊了没治疗的，约一年后离世（按月数算）；治疗满 5 年算挺过来。
- 父母、配偶、孩子的去世，父母生病：每月换算后的概率。年龄仍然一年加一次。
- **怀孕**：`conceive()` 现在是马上出生。改成怀孕约 10 个月后出生（`familyMonth` 里到期就 `haveKid()`）；怀孕期间不应再弹「要孩子吗」——`canBaby()` 在你的文件里，把怀孕考虑进去。抉择那边（C）会改成调用 `conceive()`。
- `kin.ts` 的拆迁、兄弟姐妹借钱等：`kinYear` 可以保留在生日那个月（它们本来就是年度判定），也可以改成按月，写清楚。
- 对照：`sim`（男女平均寿命 75.3/80.9、5 岁前死亡率、死因构成、人均孩子数）、`mortk`、`sib`、`par`。`MORT_K` 是为了抵消「确诊后治愈」而设的，按月以后可能要重调，写明。

### C：日程（新文件 `schedule.ts`、`content/events.ts`、`content/decisions.ts`、`education.ts`、`career.ts`）
钩子：`planYearSchedule()`、`planMonth(m)`、`scheduleYearStart()`。
- 随机事件：从「每年排 2–3 件」改成按月安排。目标：每个年龄段每年的事件数，以及常见事件（裁员、离婚、升职、被骗……）一年的发生率，和基准（`density`、`sim`）相差在一成以内。方法自己选，写清楚。
- 抉择：由状态触发的（待业找工作、生病要治疗、还不上房贷、父母病了、继承……）改成按月检查，状态一出现，最多一两个月内就弹出，不再等到下一年；本来就是「每年有一定概率」的（买房、跳槽、去大城市……）用 `perMonth` 换算，或者「每年判定一次、落在随机的月份」。别的文件里的年度判定函数（`turns.ts` 的 `listDue`、`kin.ts` 的 `demolDue`）请按「每年调用一次、落在随机的月份」来用，不要每月调用（那两个文件不归你改）。
- 学校的日历：中考、高考在公历 6 月，毕业在 6–7 月，开学（上小学、初中、高中、大学）在 9 月。现在是在生日那个月入学、按年龄判断 `schoolEnd`，要改成按日历。
- 「要孩子吗」选「要」以后，改成调用 `conceive()`（B 会把它改成怀孕 10 个月）。
- 里程碑在生日那个月。退休在生日那个月即可。
- `loveQueue()`（认识人）现在在 `planYearSchedule` 里调用，它归 D 改；D 会把认识人改成按月，到时候这里的调用由合并的人处理，你先别动它。
- 对照：`density`、`sim`（学历分布、职业）、`diag`、`crisis`。

### D：感情与状态（`romance.ts`、`stats.ts`、`focus.ts`）
钩子：`loveMonth(m)`、`bodyMonth(m)`、`driftMonth(m)`、`focusMonth(m)`。
- 健康、幸福、人际每月向目标值靠拢（`approachPerMonth`）；工作对身心的影响、上了年纪学识下降，每月 1/12。
- 每年的重心：每月按这个月在各个重心上花的时间结算（效果 1/12）；工作很拼时涨工资的机会按月换算。
- 恋爱中的感情每月变化（靠拢 + `sdPerMonth` 的波动），分手、见家长按月换算。
- 认识人：每月按换算后的概率判定，认识了就在下个月排一个「要不要在一起」的抉择（往 `S.queue` 里放，注意排序）。`loveQueue()` 的调用在 C 的 `schedule.ts` 里：你把 `loveQueue()` 改成什么都不做（保留函数），新的逻辑放在 `loveMonth` 里。
- 对照：`marr`（初婚年龄、不婚比例）、`love`、`diag`、`sim`（结婚比例）。`MEET_K`、`BREAK_K`、`READY_K` 等可以重调，写明。
