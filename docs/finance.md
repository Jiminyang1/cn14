# 财务模型（2026-10-17）

这次修改重建了收支与资产的记账方式。旧文档里的 `SAVE_BASE`、`WEALTH_MPC`、`RET_DRAW`、`PAR_DRAW` 和欠款冻结公式已经停用。存档格式从 7 升到 8，旧格式需要重新开始；过往人生记录保留。

## 现金、债务和房产

- `money` 是可用现金，不小于零；`debt` 是其他欠款。事件支出超过现金的部分记为欠款，现金收入先到账，月底再按实际余额还债。
- 房贷单独记余额、剩余期数和逾期额。每月先计息，再用公积金和现金实付；没有付款就不能减少贷款余额，贷款到期也不会自动清零。逾期额已经包含在余额中，计算净资产时不能重复扣。
- 继承先结清遗产内的债务。现金到账，房产另记为权益；明确选择出售后才变成现金，按估值的 95% 到账。完整产权可以选择搬入，共有份额不能直接当作自己整套住房。
- 净资产 = 现金 − 其他欠款 + 公积金 + 自有住房估值 + 继承房产权益 − 房贷余额。它不等于能立刻花的钱。

## 每月生活预算

本人和父母使用 `budget.ts` 的同一套规则。以当地年人均消费的 1/12 为单位，基本生活按成人 0.55 单位计，退休成人减 10%；孩子按年龄为 0.35 / 0.5 / 0.6 单位。可选消费随家庭到手收入变化，消费习惯每月向目标调整 8%。退休后保留退休前消费习惯的 85% 下限。

这些权重、调整速度和习惯下限都是游戏估计。它们不依赖现金余额，所以相同收入、家庭构成和消费习惯下，基本生活和可选消费一样多；积蓄多的人另有一项「动用积蓄的花销」（见下节）。父母家的房贷同样从真实余额扣，退休后的结余也可以存下来。

## 动用积蓄（2026-10-17）

手里的积蓄多了也会花掉一些：旅游、换车装修、帮衬子女、看病保健、人情往来。本人和父母共用 `budget.ts` 的 `savingsDraw`，参考 1in8b 的 drawOf：

- 当地人均可支配收入 20 倍（`DRAW_K`）以内的积蓄，每年花一个比例：在职 2%（`DRAW_WORK`）；退休后 75 岁前 3%、75–84 岁 4%、85 岁以后 5%（`RET_DRAW`）。超出 20 倍的部分每年只花 1.5%（`DRAW_HI`）。父母按年纪大的那一位、都退休以后按退休的档。
- 不是按余额硬扣：只从留够周转金（一个月基本生活和房租）以后的现金里出，欠着钱时多余的现金先还债，所以不会因此借钱。
- 收入不够日常开销（基本生活、房租或养老院、房贷）的，本来就在用积蓄填缺口，额外花的扣掉这个缺口。
- 账单里单列一行「动用积蓄的花销」（`savingsSpend`），不混进可选消费。

比例是估计（「4% 法则」上下，越老花得越多）。1in8b 的 4% / 6% / 8% 在这里让老人积蓄见底得太快，之后的养老院费用都记成欠款，所以取低一档。

月末顺序是家庭往来、收入及公积金转入、基本生活、住房、其他欠款利息与还款、可选消费、动用积蓄的花销、存款利息。保留约一个月基本生活和房租作为周转金，可选消费不会主动借钱。基本生活不足时记录生活缺口并影响健康；未付房租计入欠款，房贷不足计入逾期。子女向父母的补贴不超过自己当时的现金。

存款按年 1.5%、其他欠款按年 4% 换算月利率，父母账上的现金短缺沿用年 2% 的简化规则。这些是固定模型参数，不代表未来利率预测。房贷沿用各类贷款的利率。

## 可核对的账单

“我的经济”首先显示自己的现金、月度收入、生活与还款、现金变化；资产收入详情和父母财务分别折叠。父母仍影响家庭支持、赡养和继承，但默认不再展示整套父母账目。

独立的“收支账本”保存经济独立后每一个月的账单，默认只显示最新结算月份；点击“查看历史账单”后，才展示年份筛选、历史汇总与月份列表，点开月份查看详情。人生结束后仍可查看逐月记录。账单记录在当前存档中，每次月底结算后自动保存。

```
期末现金 = 期初现金 + 期间事件净额 + 月底转账 + 家庭到手收入 + 存款利息
         − 基本生活 − 孩子开销 − 房租 − 现金房贷 − 其他还款 − 可选消费
```

公积金直接还房贷、欠款计息及房贷计息另列，避免当成现金支出重复扣除。事件发生在两次月底之间时，会进入下一个月账单的“期间事件与转账”。结算页累计收入、日常消费、现金还贷与还债，并用现金差额展示事件、资产转账和利息的合计净影响。

添加月度历史兼容格式 8 的现有存档，不需要重新开始：保留已有的最后一张账单，之后逐月追加。更早月份没有记录就明确显示缺失，不根据最终余额反推。校准用的无界面人生只保留最近一张账单，避免生成不需要的 UI 历史。

大事记在一个年龄年结束后显示简短的“年终小结”，默认只写现金增加或减少多少，展开后查看收入、支出和逐月账单。当前尚未结束的年龄年不显示汇报，离世时未满的一年也不生成年度汇报。年龄年按生日划分，跨公历年的月份也归到正确的年龄下；只按已保存账单汇总，不增加模拟事件或改变收支。

## 检查结果与边界

`tests/finance.test.ts` 检查现金与欠款分离、相同收入不同现金的消费（基本生活和可选消费一样，只有动用积蓄的花销不同）、动用积蓄按年龄分档和 20 倍封顶、不同养老金、无钱时房贷不减少、补齐逾期、零利率还款、公积金扣款、父母房贷、继承资产及完整人生逐月对账。另有固定种子快照和重放测试。

4000 个固定种子（`npm run calib -- money 4000`）的检查：全部跑完、无报错；30 / 40 / 50 岁现金中位数约 6.4 / 14.4 / 25.2 万，60 / 65 / 80 / 90 岁约 59.0 / 73.2 / 50.0 / 36.5 万，离世时约 35.6 万。实际经常收支现金结余率约 −3.6%，包含现金房贷、还债和动用积蓄的花销，不包含期间事件和资产转移（继承、公积金销户这些进账是靠它们才能花的）。

加动用积蓄以前，晚年现金一直增长：工资期积蓄、父母结余和继承、公积金销户，以及养老金覆盖生活后剩下的钱和利息都会累积，60 / 80 岁中位数约 104 / 180 万，离世时约 135 万，一生中存款超过 1000 万的人生 6.80%（真实人群里千万可投资资产的家庭不到 1%）。现在存款在 65 岁前后最多、之后慢慢花掉，超过 1000 万的 0.40%。上述结果是当前模型输出，尚未验证为真实人群的财富分布。固定地区价格和长期利率、父母及成年子女的简化收入、装修换车与长期照护成本等都还需要独立校准。不能将经常现金结余率直接和统计局居民储蓄率对比，也不能为压低晚年现金而按余额强制扣消费（动用积蓄只花周转金以外的现金，收入不够开销时不额外花）。

9 种策略各 50 局的边界检查无运行报错、无现金为负或非有限数问题；仍能出现老年巨额欠款，以及高负债时选择婚育的路径。大额事件的借款约束与债务处置还没有完整建模，不能据此宣称经济平衡已经校准完成。

复查命令：`npm test`、`npm run build`、`npm run calib -- money 1500`。具体一局用 `npm run replay -- <局ID>` 核对。

## 彩礼（2026-10-17）

你自己结婚和兄弟姐妹结婚用同一套规则（`kin.ts` 的 `famPayBride`、`sibWed`）：娶亲的，父母在世就由家里出彩礼，不够的部分父母去借，记成家里的欠款；父母都不在了才自己出。出嫁的，彩礼一半做陪嫁进你的存款，另一半留在娘家；父母都不在了，整笔做陪嫁。酒席的钱自己出。原来男主角一律自己出，婚后欠着钱的男主角 54%，其中父母存款超过 10 万的 38%；现在分别是 9.4% 和 5.3%（婚前就欠着钱的 12%）。

## 动用积蓄和彩礼的校准（改前 → 改后）

| 一生中存款超过 1000 万 | 6.80%（其中继承超过 300 万的 206 个） | 0.40%（12 个） |
| 离世时欠着钱 | 6.8% | 11.3% |
| 一生买过房 / 急着卖房 / 法拍（`loan`） | 83% / 8.2% / 2.2% | 83% / 9.1% / 2.5% |

**离世时欠钱的多了。** 这些人多数住进了养老院、养老金一年只有两三万，养老院费用大于收入，缺口按「未付房租计入欠款」一直记成欠款（中位约 4.8 万）。积蓄花得越多，这个缺口越早暴露。调取用率压不下去（几组比例都在 10%–12.7%），根子是老人收入不够基本开销时没有兜底：重构以前这部分由子女、亲戚和低保兜底，不记成自己的欠款。这一块还没做。
